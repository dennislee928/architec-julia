# TTFX Baseline — First-Run Study (2026-07-17)

Machine: Apple Silicon macOS (Darwin 25.5.0) · Julia 1.12.6 · fresh depot
Harness: `bench/run.sh` (each measurement in its own process)

## Results

| Package | Cold precompile (s) | Load `using` (s) | TTFX first call (s) | Invalidated methods | Invalidation trees |
|---|---:|---:|---:|---:|---:|
| CSV | 18.1 | 1.18 | 0.02 | 973 | 33 |
| DataFrames | 45.0 | 2.07 | 0.05 | 1262 | 52 |
| Plots | 55.2 | 4.58 | 0.86 | 1539 | 58 |

Supporting observation: the initial environment build precompiled 180 dependencies
in 270 s (Plots alone 62 s).

## Interpretation (lean lens)

1. **The mobilization cost has moved, not vanished.** On Julia 1.12 with pkgimages,
   runtime TTFX is largely solved for these packages (first plot: 0.86 s — the
   legacy "time to first plot" was once ~10-30 s). The start-up loss has been
   shifted **left into precompilation**: 18-55 s per package on any fresh
   install/update. That is Front-End Planning working as designed — but the
   front-end itself is now the WIP pile. Precompile-time reduction is where
   TTFP contributions land today.

2. **Invalidations are the rework signal.** Loading Plots invalidates 1539
   already-compiled methods across 58 trees; even lean CSV invalidates 973.
   Every invalidated method is compiled work thrown away and redone — the exact
   analogue of rework from a late design change. `invalidation_trees` output
   (rerunnable via `bench/invalidations.jl`) identifies which method
   redefinitions trigger the biggest cascades: each large tree is a candidate
   upstream PR (usually a small type-annotation or dispatch fix).

3. **Load time scales with dependency surface** (CSV 1.2 s → Plots 4.6 s even
   with all pkgimages cached). This is inventory carrying cost: code loaded but
   not yet needed. It connects to the Track-B tree-shaking agenda
   (StaticCompiler.jl / juliac).

4. **Measurement note**: Plots TTFX varied between runs (0.86 s vs 3.6 s)
   depending on whether the `FileIOExt` package extension was already
   precompiled — extension precompilation is lazy and can ambush first use.
   A future harness revision should pin extension state explicitly.

## Recommended Phase 2 target

**Invalidation-reduction PRs, starting from the DataFrames/Plots trees** (52/58
trees, concrete and enumerable): rerun `bench/invalidations.jl`, take the top
tree by number of children, and fix the triggering method upstream. It is
review-sized, pure Julia, mentorable, and measurable before/after with this
harness — exactly the scope agreed in plan.md §2. Precompile-time profiling
(`SnoopCompile.@snoop_inference`) is the fallback if the top trees are already
claimed upstream.
